UnBotTrace 1.1.1 — панель для записи экрана при диагностике кика

С 1.1.1 обычная канальная переписка, переданная сервером как системные
сообщения [Solo Progress] Имя: текст, и пустые строки не записываются.
Ответы серверных команд, ошибки, AutoBalance и ответы отслеживаемых ботов
остаются. Старые записи не очищаются. После обновления нужен /reload.
Проверка: начните диагностику, дождитесь сообщения Solo Progress и отправьте
обычный запрос who своему боту. Переписки в панели быть не должно, команда
и ОТВЕТ должны остаться. При проблеме пришлите полный скриншот строки.

НОВАЯ КНОПКА: «Прогнать призыв всего реестра»
- /ubtrace открывает окно. Запишите видео и нажмите отдельную кнопку внизу.
- Старт только вне боя, живым и без группы/рейда, включая офлайн-резерв.
- Берётся снимок всего текущего реестра обычных ботов, сортируется по алфавиту.
  Карантин и недоступность не исключают имя из теста. Альты аккаунта, сам игрок
  и некорректные записи пропускаются; количество пропущенных сообщается.
- Для каждого имени по одному разу: .playerbot bot add ИМЯ, UninviteUnit(ИМЯ),
  .playerbot bot remove ИМЯ. Между командами 1 секунда: около 3 секунд на бота.
  Имя первого бота показывается за секунду до первой команды.
- Никого не ждём и не проверяем ответы. Не отправляем who, init или повторный add.
  Проверяются только бой, смерть, конфликтующий сервис, заполненность группы
  перед add и общий таймаут. Это не ожидание появления бота.
- «Остановить» отменяет будущие команды. При остановке/кике/выходе фоновая
  очистка не запускается: текущий или запоздалый бот может остаться в группе.
  Итог означает отправку команд, а не подтверждённое удаление всех участников.
- Допустимо до 5000 имён, таймаут — 4 секунды на имя плюс 30 секунд.
  После зависания кадра нет залпа команд. После входа прогон не возобновляется.
  Пассивный лимит 15 минут на активный прогон не распространяется.
- На видео важны и несколько предыдущих имён: серверный разрыв может запоздать.
  Дополнительно можно запустить /ubtrace sweep.

Это отдельный аддон для WoW 3.3.5a. UnBot заменять не нужно.
При UnBot 6.38.90 видны его внутренние этапы и сообщения. Без него доступны
вызовы стандартных API, ответы опрошенных ботов и изменения группы.

1. Полностью закрыть WoW, распаковать папку UnBotTrace в Interface\AddOns.
2. Зайти в игру, включить UnBotTrace в модификациях.
3. Ввести /ubtrace, нажать «Начать диагностику».
4. Перетащить окно так, чтобы оно оставалось видимым и не закрывало «Призвать».
5. Включить привычную запись экрана, призвать проблемный состав, дождаться кика.
6. Остановить запись экрана и передать видео с читаемой панелью.

В UnBot 6.38.90 включение галочки «Лог призыва» также открывает и запускает
UnBotTrace. Вход в игру сам новую запись не начинает. /ubtrace start и
/ubtrace stop — ручные команды. Закрытие панели не останавливает сбор, но
для видео окно должно оставаться видимым. Повторное «Начать» во время записи
не сбрасывает события; после остановки новый запуск создаёт новый журнал.

Панель показывает бота, этап, последнюю команду, состав и десять последних
событий с временем и номером. Пик — число наблюдаемых API-вызовов в секундном
интервале, а не измерение серверного лимита и не доказательство причины кика.
SendChatMessage/InviteUnit после вызова не подтверждают принятие сервером.

В памяти остаются два последних запуска, до 1000 событий каждый, строки
ограничены 700 байтами с пометкой усечения. Диагностика прекращается через
15 минут в режиме обычного наблюдения. Вызовы API логгер не заменяет.
Обычное наблюдение не отправляет команды и не меняет состав. Только явно
запущенная кнопка прогона выполняет призыв/исключение/remove.
Реестр и настройки UnBot не изменяются, серверный debug не включается.
Ошибка логгера останавливает диагностику и дальнейшие шаги теста.
Системные/UI-сообщения фиксируются как контекст, а не диагноз.

Дополнительно WoW может сохранить журнал в
WTF\Account\<аккаунт>\SavedVariables\UnBotTrace.lua при /reload/штатном выходе.
При кике/аварии этот файл может не обновиться. Поэтому для этого теста основной
материал — видео. Сам аддон видео не записывает и не пишет файл непрерывно.
Очень быстрые события между кадрами могут не попасть на видео целиком;
полнота всех событий при дисконнекте не гарантируется.


UnBotTrace 1.2.0 — запись боя и таймеров DBM
После обновления выполните /reload. Перед входом в подземелье или перед пулом:
/ubdbmlog start
Ожидается: [DBM log] Запись начата. Повторный start не сбрасывает запись.
После одного боя: /ubdbmlog stop, затем /reload для записи SavedVariables.
/ubdbmlog показывает состояние. Лимит: 20 минут или 20000 событий; два последних журнала.
Журнал: WTF/Account/<аккаунт>/SavedVariables/UnBotTrace.lua, таблица bossRuns.
Полный combat log: Logs/WoWCombatLog.txt. Старый файл дополняется, а не очищается.
Записываются отметки времени, состав/режим, касты и ауры враждебных существ, реплики,
события DBM Pull/Wipe/Kill, TimerBegin/Start/Stop/Update, Announce и Debug, настройки
и определения таймеров модулей. TimerBegin может содержать выключенный таймер;
его наличие не доказывает отображение полосы. Обычный урон/лечение — в native combat log.
DBM DebugLevel временно становится 3 и возвращается при остановке, если пользователь
не изменил его. DebugMode не включается; чат не перехватывается, команды ботам не отправляются.
Если native log был выключен, запись включает его и выключает при остановке. Если он уже
писался, остаётся включённым. Если другая система остановит combat log, журнал отметит
COMBAT_LOG_STATE=false без повторного включения. /reload во время записи завершает её.
При аварийном закрытии несохранённая часть журнала может быть потеряна.
